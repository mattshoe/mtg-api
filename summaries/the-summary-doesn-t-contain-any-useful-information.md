What was wrong: A done task's Summary was its release note, one changelog line written for the release. It said what shipped and nothing about what had been broken, why, or what the builder decided.
Why: The summary feature reused the release note because it was the only per-request text on main. Nothing asked a builder for an account of the work anywhere the app could read.
Fix: Builders now write summaries/<request name>.md. A bug says what was wrong, why and the fix, or that it would not reproduce. A feature says what was built, the choices made and the liberties taken. The task page shows that, on the phone and the website, and falls back to the release note for the 38 requests done before this. CI fails a pull request that files a request with no writeup, or one missing a line.
