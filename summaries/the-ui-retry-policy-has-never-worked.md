What was wrong: The 3-retry policy on Android UI tests never retried a Compose test. A flaky test failed once, the retry ran it again on the same compose rule, Compose refused with "Only a single call to runTest can be performed", and that coroutine error was the failure reported instead of what actually broke.
Why: Retry was a JUnit rule. A rule can only re-run the statement it was given, and that statement belongs to one test instance with its rules already built, so the second attempt reused the used-up compose rule.
Fix: Retrying moved into the test runner. Each attempt builds a fresh test instance with fresh rules, on Robolectric and on the device runner both. AndroidJUnit4 is pointed at the retrying runners through its own android.junit.runner setting, so every UI test retries without declaring anything and the per-class rule is gone. A retried test is still one result, a skipped test still runs once, and a test that fails all four times reports the first failure. This is test tooling only, nothing changes in the app on the phone or the website.
