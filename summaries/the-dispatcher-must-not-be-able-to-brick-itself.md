What was built: The dispatcher still runs the scripts as they are on main, but when main's copy is plainly broken it runs the laptop's working copy for that tick instead, and the log says RUNNING UNMERGED CODE, why, and which branch. Plainly broken means one of two things: main's copy is missing a script the dispatcher needs, or the inbox or task status script cannot find the requests folder, which is exactly what killed the queue for twelve hours. Before, that showed up as an ENOENT line every minute and nothing else.
Choices: The two task scripts now stop with a special exit code when they cannot see the requests folder, checked before they look for a login, because the tests have no login and that is how the original bug got past them. A failed network call or a server error does not count, so a bad day keeps running main's code. The tests break main's copy on purpose and check that the fallback happens and a task still starts.
Liberties: Fixed two more bugs found on the way. When main's scripts could not be read at all, the dispatcher crashed on a variable it had not set yet, instead of carrying on. And the dispatcher passed its pinning settings on to the agent it starts, so an agent running the dispatcher tests pointed them at the real repo. That happened while this was being built, a test's fake agent made a commit in the real agent folder. Nothing was written to the task board because the tests have no login.
